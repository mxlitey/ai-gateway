# AI Gateway 插件开发规范

本文档面向第三方插件作者。读完这一篇，你应该能独立写出一个可用的插件：
把它放进 `plugins/<插件id>/`，网关启动后会自动拉起、探活、注册为一个渠道，并在面板里出现。

---

## 1. 插件是什么

**一个插件就是一个独立的本地进程**，用 **Python** 写成，通常是一个 HTTP 服务：

```
              ┌──────────────────────── AI Gateway（单二进制） ────────────────────────┐
客户端 ──/v1──▶ 代理层（密钥校验 / 负载均衡 / 故障转移 / 用量统计）                    │
                   │                                                                │
                   │ 按渠道把请求转发到                                              │
                   ▼                                                                │
            插件渠道  http://127.0.0.1:<你自选的端口>/v1/...  ───────▶ 插件进程（你写的）│
                   ▲                                                                │
面板 ──/admin──▶ 插件宿主（发现 / 启动 / 探活 / 重启 / 回收 / 渠道注册 / 控制台代理）   │
              └────────────────────────────────────────────────────────────────────┘
```

宿主负责：

- 扫描 `plugins/` 目录、校验 `plugin.json`
- 读取你在清单里自选的端口、注入环境变量、拉起进程
- 轮询探活，不健康时自动重启（带退避），退出时回收整个进程树
- 把插件注册成一个渠道（`source = plugin:<id>`，渠道名 = 插件 `name`），插件停用则渠道自动停用
- 转发面板对插件控制台的调用（见 §6）

插件负责：**实现一个 OpenAI 兼容（或任意协议 + 自转换）的上游**，以及可选的控制台接口。
插件进程不接触网关数据库，凭据由插件自己保管（放在宿主编入的私有数据目录里）。

## 2. 最小可用插件

**网关只支持 Python 插件**：插件就是一段 Python 源码，宿主负责解析解释器并拉起它。
同一份 `main.py` 原样复制到 Windows / macOS / Linux（含 Docker）都能跑，
不需要为各平台准备不同的启动壳或编译产物。

目录结构（**目录名就是插件 id**：总长 2–32 位，首字符必须是字母或数字，其余可用小写字母/数字/`-`/`_`）：

```
plugins/
└── hello/
    ├── plugin.json      # 清单：必须叫这个名字
    └── main.py          # 你的程序：清单里 entry 指向的 .py 脚本
```

`plugin.json`：

```json
{
  "name": "Hello 示例插件",
  "entry": "main.py",
  "port": 20723
}
```

必填只有三个：`name` / `entry` / `port`。其余都是可选的（见 §3）。

固定约定（不用声明）：

| 约定 | 值 |
|---|---|
| 监听地址 | `127.0.0.1:<port>` |
| 上游根路径 | `/v1`（对话 `POST /v1/chat/completions`，模型列表 `GET /v1/models`） |
| 探活 | `GET /health` |
| 控制台前缀 | `/console`（声明 `"console": true` 后才有） |

> **插件只需要实现 OpenAI 协议。** Claude 协议入口 `POST /v1/messages` 由**网关自己**提供：
> 它把 Claude 请求转成 OpenAI 形状，再打到你的 `/v1/chat/completions`，返回时再转回 Claude 形状。
> 也就是说插件**永远收不到** `/v1/messages`，也**不需要**为它做任何事——
> Claude 客户端（如 Claude Code）想用上你的插件，你什么都不用改。
> 下文提到「Claude 入口」时，指的都是**客户端**调用的端点，与你要实现的东西无关。

程序至少要提供两个接口：

| 接口 | 作用 |
|---|---|
| `GET /health` | 探活。返回状态码 < 500 即视为健康（3xx/4xx 也算存活）。**只反映插件进程自身**，见 §7 |
| `POST /v1/chat/completions` | 实际转发目标。返回 OpenAI 兼容响应 |

`GET /v1/models` 只在你要让用户在「渠道管理」里点「获取上游模型」时才需要，**形状必须是 OpenAI 的**：

```json
{ "data": [ { "id": "你的上游模型名" } ] }
```

> 模型不会自动进渠道：即便实现了 `/v1/models`，用户仍要在「渠道管理」里编辑该渠道、点「获取上游模型」后勾选。
> 插件**无法自行注册模型**。
>
> 勾选之后客户端就能用了——渠道的 `models` 里命中即可**同名透传**，**不需要**再去「模型路由」建映射；
> 只有当你想把上游模型暴露成**别的公开名**时，才需要去「模型路由」做映射。
>
> 注意：宿主「获取上游模型」时会以 `X-Plugin-Account` 头调用你的 `GET /v1/models`（规则同 §5），
> 所以别对不认识的账号值直接返回 `4xx`，否则模型列表拉不出来。

上面是最小形态的示意（`hello` 只是示例名），**不宜直接照抄上线**。
仓库里可直接运行的参考实现：

- `examples/hello-py/` —— 只用标准库的最小实现，最适合当起点；
- `examples/trae/`、`examples/workbuddy/` —— 完整实现（控制台、多账号、签到、额度与多种登录方式）。

把目录整个复制到 `plugins/<id>/` 后点面板「重新扫描」即可拉起。

## 3. `plugin.json` 字段参考

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `name` | string | ✅ | — | 展示名，同时也是渠道名 |
| `entry` | string | ✅ | — | 入口脚本，**必须是插件目录内的 `.py` 文件**（相对路径，不允许绝对路径或 `..` 逃逸） |
| `port` | int | ✅ | — | **插件自己监听的端口**（1–65535），由你选定；被别的程序占用时会在面板上报错 |
| `version` | string | | `""` | 仅用于展示 |
| `description` | string | | `""` | 仅用于展示 |
| `args` | string[] | | `[]` | 传给入口脚本的额外参数，支持 `{{port}}` |
| `env` | object | | `{}` | 追加的环境变量，值支持 `{{port}}` |
| `console` | bool | | `false` | 是否提供控制台（实现 `/console/*` 约定接口，见 §6） |
| `capabilities` | string[] | | `[]` | 控制台能力：`checkin` / `quota`，见 §6.1 |
| `requirements` | string[] | | `[]` | Python 依赖，格式同 `requirements.txt`，由宿主安装到插件私有目录（见 §11.2） |

### 3.1 高级（通常不用写）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `startup_timeout_ms` | int | `20000` | 启动后等待探活通过的最长时间，慢启动的程序可以调大 |
| `python_version` | string | `3.12` | 期望的便携 Python 版本（仅用于下载；不满足也不会阻止用系统 Python 启动） |

**端口规则**：`port` 由你自己选定并写死在清单里（1–65535）。网关只做两件事：把它注入到
`AI_GATEWAY_PLUGIN_PORT` 和 `{{port}}`，以及启动前确认它没被别的程序占用——被占用时插件会以
`failed` 停在面板上并给出提示，换一个端口即可。不存在「自动分配」。

`port` 是**主服务端口**，网关只会往它发探活、`/v1/*` 与控制台请求。

**插件不得再监听任何额外端口。** 典型场景「`link` 类登录需要本机 OAuth 回调页」已由网关统一托管：
网关开放了一个统一回调入口 `/plugin-callback/<插件id>/...`，插件把回调地址拼出来即可，无需自己监听
（见 §6.7）。插件只应监听清单里的 `port` 这一个端口。

## 4. 环境变量

宿主会注入这几个变量（无需声明）：

| 变量 | 含义 |
|---|---|
| `AI_GATEWAY_PLUGIN_ID` | 插件 id（= 目录名） |
| `AI_GATEWAY_PLUGIN_PORT` | 你清单里选的端口，**直接监听这个端口** |
| `AI_GATEWAY_PLUGIN_DIR` | 插件目录的绝对路径（只读，升级会被整体覆盖） |
| `AI_GATEWAY_PLUGIN_DATA` | 插件私有数据目录（可写，放凭据/缓存；不要写进插件目录） |
| `AI_GATEWAY_CALLBACK_BASE` | **统一登录回调入口**的基址（不含 method/state），见 §6.7 |

> 建议：端口读 `AI_GATEWAY_PLUGIN_PORT`，数据一律落 `AI_GATEWAY_PLUGIN_DATA`。
> `{{port}}` 占位符只在 `args` / `env` 里可用，等价于 `AI_GATEWAY_PLUGIN_PORT`。
>
> 补充：插件进程的**工作目录（CWD）就是插件目录本身**，所以「相对路径」是相对插件目录解析的；
> 但不要把插件目录当成可写盘——可写内容一律放 `AI_GATEWAY_PLUGIN_DATA`（见 §10）。

`AI_GATEWAY_CALLBACK_BASE` 形如 `http://127.0.0.1:8787/plugin-callback/<你的插件id>`。
它是**进程启动时**算出来的，进程运行期间不会变；但每次登录请求还会用请求头
`X-Gateway-Callback-Base` 覆盖它（见 §6.7）——**请优先读请求头**，这样改了外部域名、
换了访问入口都不需要重启插件。

`AI_GATEWAY_PLUGIN_DATA` 是唯一**不会被升级覆盖**的目录，凭据与缓存都放这里。
如果你在数据目录里存了自定义结构，建议自己放一个 schema 版本标记（例如 `state.json` 里的 `"schema": 2`），
升级时据此迁移——`plugin.json` 的 `version` 只用于面板展示，网关不会用它触发任何升级逻辑（见 §10）。

## 5. 选号：账号即渠道密钥

网关统一按「账号」调用插件——**渠道密钥 = 账号 id**，转发时带 `X-Plugin-Account: <账号 id>`。
清单里没有任何密钥字段需要你声明，单账号和多账号是同一条路径。

- 只要 `"console": true`，宿主就会读取 `GET /console/accounts`，
  把每个账号同步成插件渠道里的一条密钥：**密钥值 = 账号 id、展示名 = 账号名**；
- 网关转发（`/v1/*`）时带 `X-Plugin-Account: <账号 id>`；探活（`GET /health`）与控制台调用**不带**该头；
- 于是「轮询 / 故障转移」「启用停用」「先后顺序」全部由用户在网关的渠道页配置，
  你的插件只需按收到的账号 id 选号即可。
- 只有一个账号时，渠道里就只有一条密钥——这就是「单账号」的全部含义。

插件侧实现要点：

```python
def account_for_request(handler):
    """命中 X-Plugin-Account 就用该账号，否则回退到自动挑号（兼容直连调试）"""
    acc_id = handler.headers.get("X-Plugin-Account") or ""
    if acc_id:
        acc = store.get(acc_id)
        if acc is not None:
            if not acc.enabled:
                raise AccountDisabled("账号 %s 已在插件侧停用" % acc_id)
            return acc
    return pick_account()
```

- 账号增删只在控制台里做，宿主会自动把变更同步到渠道密钥（账号变更后立即同步，运行期间约每 30 秒复查一次），无需人工操作；
- 账号列表为空时该渠道没有可用密钥，网关返回 `503 无可用渠道`（而不是打到你这边再报错）；
- 账号不可用请返回 `401` / `403` / `429` / `5xx`——网关会切到下一个账号（故障转移），
  或在下一次请求轮到别的账号（轮询）；**请求本身的问题请返回 `400`**，否则账号会被无谓地轮换一遍（见 §5.2）。

不声明 `console` 的插件没有账号概念，此时 `X-Plugin-Account` 的值固定为占位值 `gw-local`，
不承载语义，你可以忽略它（插件只监听回环地址，本机调用即可）。

**转发时的请求头规则**（插件侧不用、也无法自己做鉴权）：

| 头 | 网关行为 |
|---|---|
| `X-Plugin-Account` | `/v1/*` **一定带**（含宿主拉模型列表的 `GET /v1/models`）。值为渠道密钥 = 账号 id；未声明 `console` 时为 `gw-local` |
| `Authorization` / `x-api-key` | 插件渠道**不带**；客户端传来的同名头会被网关剥离，不会透传给你 |
| `cookie` | 同样被剥离，不透传 |
| 其余客户端头 | 原样透传 |

鉴权在网关完成，插件只按 `X-Plugin-Account` 选号即可。探活（`GET /health`）与控制台调用**不带**该头，
所以上面示例代码里保留了「头缺失时自动挑号」的兜底——它只服务于直连调试，正常转发一定带该头。

**职责边界（硬约束）**：**「轮到哪个账号」这件事全部归网关**——轮询 / 故障转移 / 先后顺序 / 冷却降级
都由用户在渠道页配置，插件不得自行改变调用顺序：不要在内部分流、跳号、按积分挑号，也不要自己做冷却或降级。
你只需做两件事：收到哪个账号就用哪个；该账号不可用就**如实返回 `4xx/5xx`**（见上一条），
由网关决定切下一个还是等下一轮。

> 注意区分：账号的"可用 / 不可用"仍由你通过 `enabled` / `last_error` 声明（见 §6.4），
> 那是**状态上报**，不是调度——上报之后用不用它，仍然是网关的事。

### 5.1 转发契约（超时与流式）

| 项 | 网关行为 | 对你的要求 |
|---|---|---|
| 连接 / 等响应头 | 建连 15 秒、等上游响应头最长 120 秒；**没有整体超时** | 必须在 120 秒内开始返回响应头，否则判定失败并切下一个目标 |
| 非流式 | 读完整包后再回给客户端；`200` 且是 `chat/completions` 时会校验响应体里确实有 `choices` | 返回标准 OpenAI JSON |
| 流式（客户端 `stream: true`） | 若你返回 `Content-Type: text/event-stream`，网关**逐块实时转发**（不缓冲），并把事件里的 `id` 统一改写 | 边收边发即可，不要先攒完整包 |
| 流式但返回了非 SSE | 网关记一条警告并**回退为非流式处理**：把整包 JSON 当作一次响应返回给客户端 | 这样也能用，但客户端拿到的是"一次性完整响应"，失去流式体验 |

> 结论：**流式请求建议真的流式返回**；如果你的上游只能整包拿（例如它自身不支持 SSE），
> 那就直接返回 OpenAI 的整包 JSON，网关会兜住——但请让客户端知道这不是真流式。

### 5.2 错误语义：什么时候该切号

网关按你返回的 **HTTP 状态码**决定要不要换下一个目标，只有一条特例（见下表第 2 行）。
这条规则对普通渠道和插件渠道一视同仁；客户端走 Claude 入口时，网关先把请求转成 OpenAI 再打给你，规则不变。

| 你返回 | 网关行为 | 用在什么场景 |
|---|---|---|
| `2xx` | 正常回给客户端 | 成功 |
| `200` 但响应体其实是错误 | **切号**（特例：这条不看状态码，看响应体） | 「假成功」：体里有 `error` 字段，或 `choices` 缺失 / 为空 |
| `401` | **切号** | 这个账号的凭据失效 / 被拒 |
| `403` | **切号** | 这个账号无权限（未开通该模型、额度耗尽、地区限制） |
| `404` | **切号** | 「这个账号/这个站点没有该模型」——别的账号或站点可能有（见下方判据） |
| `429` | **切号** | 限流 |
| `5xx` | **切号** | 上游故障 |
| 连不上 / 超时 | **切号** | —— |
| 其他 `4xx`（`400` / `405` / `422` …） | **不切号**，直接回给客户端 | **请求本身的问题**：模型名不存在、参数非法、内容被拒 |

**怎么选码：网关只能看到状态码，分不清"这个账号没这个模型"和"这个模型根本不存在"——
这个判断必须由你按上游自己的错误码 / 文案来做。**

| 上游告诉你 | 你返回 | 结果 |
|---|---|---|
| 模型名不存在 / 已下线（对谁都一样） | `400` | 不切号，错误直接给客户端 |
| 这个账号（或这个站点）没有该模型 | `404` | 切号，换账号 / 站点再试 |
| 这个账号无权 / 未开通该模型 | `403` | 切号 |
| 这个账号凭据失效 | `401` | 切号 |
| 达到限流 / 额度耗尽 | `429` | 切号 |
| 上游内部错误 | `5xx` | 切号 |

一句话原则：**「换个账号可能就好了」用 `401/403/404/429/5xx`；「换谁来都一样」用 `400`。**

> 最容易踩的坑：把**全局**的"模型不存在"返成 `404`，网关就会拿这个坏模型把渠道里**所有账号轮流试一遍**，
> 把一份错误重复 N 次。只有当"模型缺失确实与账号相关"（例如你的账号分布在国内站 / 国际站，
> 某模型只在其中一站有）时，`404` 才是正确选择。

### 5.3 错误响应最终长什么样

你的非 2xx 响应体**不会**原封不动给到客户端。客户端**用哪个入口调**，决定了它看到什么形状
（你的插件始终只被以 OpenAI 形状调用，下面的差异由网关产生）：

| 客户端调用的入口 | 客户端收到的错误 |
|---|---|
| `/v1/chat/completions`（OpenAI） | 你的状态码 + **你的响应体，但只保留前 300 字节**（超出直接截断） |
| `/v1/messages`（Claude） | 你的状态码 + 固定形状：`{"type":"error","error":{"type":"api_error","message":"Upstream error: <你的响应体前 4096 字节>"}}` |

所有目标都失败时，客户端收到 `502` + `"All targets failed. Last error: ..."`
（OpenAI 入口是 OpenAI 形状，Claude 入口是 Claude 形状）。

> 建议：错误文案控制在 **300 字节以内**（中文约 100 字），否则 OpenAI 入口下用户会看到半句话。
> OpenAI 入口只透传你的响应体、不重塑结构；Claude 入口的结构由网关决定，你的原文会落在 `message` 里。

## 6. 插件控制台（可选，但推荐）

插件常常需要「账号登录 / 多账号 / 签到 / 额度」这类管理界面。
网关不要求你写前端，也不允许把用户赶到另一个网站的页面上——
你只要在 `plugin.json` 里写 `"console": true`，并按下面的**约定接口**实现 REST，
面板就会用统一风格把这些内容渲染出来。

### 6.1 声明

```json
{
  "console": true,
  "capabilities": ["checkin", "quota"]
}
```

控制台接口前缀固定 `/console`，标题用插件 `name`。

`capabilities` 是**可选的声明**，只影响面板渲染：

| 值 | 面板多出来的东西 |
|---|---|
| `checkin` | 「今日签到」列 + 每行的「签到」按钮；**宿主还会自动定时签到**（见下） |
| `quota` | 「套餐」「额度」列 + 每行的「刷新额度」按钮 |

两个都不声明时，控制台只有账号列表、登录按钮与「删除」。
`capabilities` 只认得这两个值（由网关版本决定，写别的会被忽略），见 §6.3。

**自动签到由宿主统一调度，插件不要自己写定时逻辑。** 声明 `checkin` 后：

- 插件每次进入 `running`，宿主会立刻补签一轮（覆盖网关 / 插件重启场景）；
- 之后宿主每小时复查一次（覆盖跨天场景）；
- 宿主只对 `GET /accounts` 里 `enabled=true` 且登录有效的账号调用 `POST /accounts/{id}/checkin`。

因此该接口必须**幂等友好**：今天已签到时返回成功语义（并附说明），而不是当成硬错误——
宿主会重复调用，靠幂等语义保证不产生副作用。

### 6.2 宿主如何转发

面板的请求走：

```
面板 ── /admin/api/plugins/<id>/console/<子路径> ──▶ 宿主（已鉴权）──▶ http://127.0.0.1:<port>/console/<子路径>
```

宿主原样透传 **方法 / 查询串 / JSON 正文 / 状态码 / 响应体**：请求体上限 1 MB，响应体上限 8 MB。
也就是说：面板请求 `/admin/api/plugins/hello/console/accounts/demo-1/checkin`
会变成对你的 `POST /console/accounts/demo-1/checkin`。

状态码语义（**谁产生的很重要**）：

| 状态码 | 产生方 | 含义 |
|---|---|---|
| `409` | **宿主** | 插件不存在 / 未声明 `console` / 未运行——「还没就绪」，不是业务错误 |
| `502` | **宿主** | 宿主连不上插件进程（通常插件刚挂了） |
| `4xx` / `5xx` | **插件** | 你的业务错误，**原样透传**：状态码与响应体都照搬，面板以 toast 展示 `error` 字段 |

插件返回非 2xx 时请带上 `{"error": "给人看的中文说明"}`（见 §6.5）；除 `error` 外的字段面板会忽略。
建议：账号不存在用 `404`，参数不合法用 `400`，插件内部异常用 `500`。

> 控制台接口**不需要**自己做鉴权：请求只可能来自本机宿主，且面板侧已经过管理员鉴权。

### 6.3 约定接口

| 方法 | 路径（相对 `/console`） | 必需 | 作用 |
|---|---|---|---|
| GET | `/accounts` | ✅ | 账号列表。面板靠它渲染，宿主也靠它把账号同步成渠道密钥、并确定自动签到的账号范围 |
| DELETE | `/accounts/{id}` | ✅ | 删除账号（面板每行都有「删除」按钮） |
| POST | `/accounts` | | 手工新增账号：**面板不调用**，仅供脚本 / 手工 curl 使用（见 §6.5） |
| POST | `/accounts/{id}/checkin` | | 签到（需声明 `checkin` 能力，见 §6.1）；宿主自动签到也走这个端点 |
| POST | `/accounts/{id}/quota` | | 刷新额度（需声明 `quota` 能力，见 §6.1） |

`id` 由插件生成，**不要包含 `/`**（会被当成路径分隔符）；账号不存在时返回 `404`。

**面板上加账号的入口是登录按钮**：用户在面板里只能通过 `GET /accounts` 返回的
`login_methods`（见 §6.6）加号——声明了 `fields` 的方法会渲染成表单（可直接粘贴 token / Cookie），
没有 `fields` 的方法则点一下由插件自己完成。
`POST /accounts` 是给脚本 / 手工 curl 用的旁路，**面板不会调用它**；
一个只实现 `POST /accounts`、不声明任何登录方式的插件，**在面板上是加不了账号的**。

注意：`capabilities` 不是自由扩展点——面板只认得 `checkin` / `quota`，写别的值不会渲染出任何新界面。
`/console/*` 下你仍可以实现**任意自定义端点**（宿主会原样透传），但面板不会替你渲染。
能被面板渲染的新能力（例如"刷新登录态"）只能随网关版本增加，第三方插件没有扩展入口；
确实需要新 UI 请给网关提需求，而不是塞 HTML——插件目录会被整体覆盖升级，那样也不可持续。

### 6.4 账号对象

```json
{
  "id": "demo-1",
  "name": "主号",
  "site": "cn",
  "enabled": true,
  "plan": "标准版",
  "credits": 1280,
  "checked_in_today": false,
  "streak_days": 3,
  "expires_at": 1760000000000,
  "last_error": ""
}
```

| 字段 | 类型 | 面板行为 |
|---|---|---|
| `id` | string | 主键，必填；渠道密钥就是它 |
| `name` | string | 账号列显示；为空则显示 id |
| `site` | string | `cn` → 国内站，`intl` → 国际站，其他值原样显示 |
| `enabled` | bool | 账号是否可用。**新建**渠道密钥时据此设置启用状态；已存在的密钥由用户在渠道页手动控制，不会被覆盖 |
| `expires_at` | number(ms) | 登录态过期时间，**毫秒**；早于当前时间显示「已过期」。⚠️ 很多上游 API 返回的是**秒**，记得 `×1000`；`0` 表示不过期 |
| `last_error` | string | 账号行下方的红色小字，**需脱敏**（不要带 token 片段） |
| `plan` | string | 套餐列（仅声明 `quota` 能力时显示） |
| `credits` | number | 额度列，带千分位；**允许小数**（如 `1280.5`，面板按原值格式化）（仅声明 `quota` 能力时显示） |
| `checked_in_today` | bool | 已签（显示连签天数）/ 未签（仅声明 `checkin` 能力时显示） |
| `streak_days` | number | 连签天数（仅声明 `checkin` 能力时显示） |

未知字段会被忽略；字段缺失显示 `—`（注意 `credits: 0` 显示 `0`，字段缺失才显示 `—`）。
**凭据（token 等）不要出现在响应里**。

> `checked_in_today` / `streak_days` 只用于面板展示。宿主自动签到不做跨天判断，
> 而是对 `enabled=true` 且未过期的账号直接调用签到端点，靠签到的幂等语义兜底。

### 6.5 各接口的响应约定

- `GET /accounts` → `{"accounts": [...], "notice": "可选提示", "login_methods": [...]}`
  - `notice`：非空时在控制台顶部显示一条**常驻提示条**（每次刷新都会显示），适合放"还没有账号，点上方按钮登录"这类引导；不需要就省略
  - `login_methods`：登录按钮声明，见 §6.6；省略则没有登录按钮
- `POST /accounts` → `{"message": "账号已加入", "account": {...}}`
  - 请求体（**面板不会调用这个接口**，body 只是给脚本用的约定）：
    `{"name": "...", "site": "cn", "token": "...", "uid": "..."}`
  - **要求 upsert 语义**：以 `id`（由你按 token/uid 推导出的稳定标识）为准，已存在则更新、不存在则新增，
    两种情况都返回成功；这样脚本可以重复执行。返回的 `message` 里可以区分「已新增」/「已更新」
- `DELETE /accounts/{id}` → `{"success": true}`
- `POST /accounts/{id}/checkin` → `{"message": "签到成功，+100 积分", "account": {...}}`
- `POST /accounts/{id}/quota` → `{"message": "额度已刷新", "account": {...}}`

出错时返回 `4xx/5xx` + `{"error": "给人看的中文说明"}`，面板会原样 toast。
接口应当是**幂等友好**的：例如「今天已签到」应返回成功语义（并附说明），而不是当成硬错误。

### 6.6 登录流程（可选）

在 `GET /console/accounts` 的响应里带上 `login_methods`，面板会把这些方法渲染成按钮
（声明了 `fields` 的方法会先展开一个表单，见下）：

| 字段 | 说明 |
|---|---|
| `id` | 方法 id，回调时用它区分。必须能安全放进 URL 路径：只用小写字母 / 数字 / `-` / `_`，**不要含 `/`、`?`、`#`、空格**（面板把它拼进 `POST /console/login/{id}`，不做转义）；建议 ≤ 32 字符 |
| `label` | 按钮文字 |
| `hint` | 可选说明，作为按钮 tooltip |
| `fields` | 可选的输入项数组：声明后面板先收集用户输入再提交（见下）。**不声明则行为完全不变**，仍是「点一下即完成」 |

> 登录方式**没有"类型"字段**：面板不看你声明什么，只看你返回的响应形状（见下）。
> 同一个方法在不同时刻返回不同形状是不允许的。

#### 让用户在面板里填东西：`fields`

面板没有自由表单——**要用户粘贴 token / Cookie / 验证码的流程，靠声明 `fields` 来实现**，
由面板渲染输入框并随 `POST /console/login/{method}` 一并提交。声明是纯增量的：
提交后你仍按下面的响应形状返回 `action`（`{"status":"ok"}`）或 `link`（带 `url`+`state`），
面板不需要知道这个方法是哪一类。

```json
{
  "id": "paste-cookie",
  "label": "粘贴 Cookie 登录",
  "hint": "在浏览器登录后，从开发者工具复制 Cookie",
  "fields": [
    { "name": "cookie", "label": "Cookie", "kind": "multiline",
      "placeholder": "MSESSION=...; ..." },
    { "name": "name", "label": "备注名", "required": false }
  ]
}
```

字段属性（**类型刻意限死三种，不做任意扩展**——面板要保持统一风格，不能变成插件自绘）：

| 属性 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | ✅ | 提交时的键名 |
| `label` | string | ✅ | 输入框上方的标签 |
| `kind` | string | | `text`（默认）/ `secret`（按密码框渲染、不回显）/ `multiline`（多行文本域） |
| `placeholder` | string | | 输入框占位提示 |
| `hint` | string | | 标签下方的补充说明 |
| `required` | bool | | 默认 `true`；显式传 `false` 允许留空 |

提交时面板 POST 的正文是 `{"<name>": "<值>", ...}`（只含声明的字段），
宿主原样透传（见 §6.2），所以你在 `/console/login/{method}` 里 `json` 读 `req.body` 即可。

三点要求：

1. **凭据绝不回显**：收到的值只落 `AI_GATEWAY_PLUGIN_DATA`，不要放进 `GET /accounts` 的任何字段
   （含 `last_error` / `message`），也不要原样回在 `POST` 的响应里（见 §6.4 / §8）。
2. **校验后如实反馈**：值无效请返回 `{"status":"error","message":"Cookie 已失效，请重新复制"}`，
   面板会 toast 该文案；不要在插件侧静默丢弃。
3. **不要把 `fields` 当自由 UI 扩展点**：它只解决"收集少量文本输入"这一件事。
   需要选择器、多步向导等复杂交互，请给网关提需求（同 §6.3 末尾的口径）。

两类都走同一个入口：

| 方法 | 路径 | 返回 |
|---|---|---|
| POST | `/console/login/{method}` | `action`：`{"status":"ok","message":"..."}`；`link`：`{"status","message","url","state"}` |
| GET | `/console/login/{method}?state=xxx` | 仅 `link` 需要，轮询用：`{"status","message"}` |

> `POST` 的正文**可携带 `fields` 收集到的值**（`{"<name>":"<值>"}`，见上）；
> 未声明 `fields` 时正文为空，与旧行为一致。

**面板如何区分两类**（只按返回体形状判断）：`POST` 的响应里**同时有 `url` 和 `state`** 就当 `link`
（打开 `url` 并轮询）；否则当 `action`（toast `message` 并刷新账号列表）。

`state` 由**你**生成、面板原样回传，用来让 `GET` 认出是哪个会话：

- 面板会做 URL 编码，所以字符集不强制，但建议只用可打印的 URL 安全字符、长度 ≤ 128；
- **每次登录必须不同**，并且你要在服务端记录它对应的会话（否则无法在 `GET` 时还原）；
- 不要把它当凭据——它只用于区分会话（面板可能把它显示在地址栏历史里）。

`status` 取值：

| 值 | 含义 |
|---|---|
| `pending` | 还没完成，面板继续轮询 |
| `ok` | 完成，面板自动刷新账号列表 |
| `error` | 失败，toast 后停止轮询 |
| `expired` | 授权已过期（与 `error` 同为终止态，提示文案由你给） |

三点务必注意：

1. **轮询没有次数上限**：只要仍返回 `pending`，面板每 2 秒问一次，不会自动放弃——直到你返回终止态，
   或用户点「取消」/关闭控制台。所以请在插件侧给 `state` 设过期时间，超时返回 `expired`，
   不要让会话永远停在 `pending`。
2. **要用户填东西有两种做法，按复杂度选**：
   - 少量文本输入（token / Cookie / 备注名）→ 声明 `fields`，面板直接渲染表单（见上），
     用户不用离开面板；
   - 更复杂的输入（验证码交互、需要在目标站页面里操作才能拿到的东西）→ 走 `link`，
     回调地址用网关的统一回调入口（见 §6.7），让用户在浏览器里完成输入。
   两种都不需要用户开终端敲 curl。
3. **面板同一时间只跟踪一个登录会话**：`link` 发起后若用户又点了另一个登录按钮，
   新会话会**替换**旧的——旧 `state` 立即停止轮询（其授权链接也随之失效）。
   所以不要设计"同时进行多个登录"的流程；被替换掉的会话请靠你自己的超时机制回收（见第 1 点）。

### 6.7 统一登录回调入口（`link` 类登录必读）

`link` 类登录需要「用户在浏览器里完成授权 → 浏览器跳回本机某个地址」。
**这个地址由网关统一提供，插件不得自己监听额外端口**（见 §3）。

```
浏览器 ── GET /plugin-callback/<插件id>/<method>/<state> ──▶ 网关（免鉴权，只放行 GET）
                                                              │ 只映射到 /console/callback/*
                                                              ▼
                                        插件进程 http://127.0.0.1:<port>/console/callback/<method>/<state>
```

#### 回调地址怎么拼

宿主在**每次登录请求**里都会带一个请求头：

```
X-Gateway-Callback-Base: https://gw.example.com/plugin-callback/<你的插件id>
```

你在 `POST /console/login/{method}` 里读它，拼上 `/<method>/<state>` 就是回调地址：

```
https://gw.example.com/plugin-callback/<插件id>/<method>/<state>
```

读取优先级（务必按此顺序，否则反代 / 隧道场景会拼错地址）：

1. **请求头 `X-Gateway-Callback-Base`**（推荐；每次登录现算，改域名无需重启插件）；
2. 环境变量 `AI_GATEWAY_CALLBACK_BASE`（进程启动时算好的兜底）；
3. 两者都没有（例如你单独调试插件、不经网关启动）→ 退回自己起临时监听。

> 第 3 条只是**直连调试的退路**：正常由网关拉起的插件，前两条一定有值。
> 单独调试时你仍可临时监听一个回环端口，但**不要把它当成正式方案**——正式运行不得额外监听。

#### 网关侧收到的请求长什么样

- 方法**只放行 `GET`**，其余一律 `405`；
- 路径原样透传到你的 `/console/callback/<method>/<state>`，查询串一并带上；
- 网关会透传 `X-Forwarded-Proto` / `X-Forwarded-Host` / `X-Forwarded-Prefix`，
  供你在返回 HTML 时生成绝对跳转地址；
- 你的响应体（HTML 或 JSON）**原样返回给浏览器**，状态码也照搬；响应体上限 1 MB；
- 插件不存在 / 未运行 / 未声明 `console` 时，网关返回**自己的**错误页（不转发）。

#### 三条硬要求

1. **必须校验 `state`**：一次性、带 TTL、不可猜。收到回调时先按 `state` 找回自己发出的会话，
   找不到或已过期就丢弃并返回失败页——**绝不能对未知 `state` 产生任何副作用**。
   该入口免鉴权（浏览器重定向带不了管理员凭据），`state` 是唯一的防伪手段。
2. **回调里的凭据只落 `AI_GATEWAY_PLUGIN_DATA`**，不要出现在任何响应里（见 §6.4 / §8）。
3. **回调页自己写**：成功 / 失败都返回给人看的 HTML（`Content-Type: text/html`）。
   面板只轮询 `GET /console/login/{method}?state=xxx` 拿状态，不依赖回调页的内容。

> 提示：把 `state` 放进回调**路径**（而非查询串）更稳妥——部分上游要求 `redirect_uri`
> 精确匹配，路径形态的地址更容易登记进白名单。

#### 上游强制固定回调地址时（`callback_paths`）

个别上游（如 TRAE、LobsterAI）只接受 `http://127.0.0.1:<端口>/...` 形式的 `redirect_uri`，
无法使用网关的统一回调入口。这类插件可以在 `plugin.json` 声明自己监听的回调路径：

```json
{ "callback_paths": ["/authorize"] }
```

- 这些路径由插件**在自身端口上**处理（与 §3「不得监听额外端口」不冲突）；
- 桌面版可直接访问；**Docker 部署时该端口只在容器内，宿主机浏览器打不开**，属于预期现象；
- 此时用户把浏览器地址栏里的完整回调链接粘贴到面板登录卡片，网关校验后转发给插件
  （`POST /admin/api/plugins/<id>/callback`；只接受回环地址、只放行 `callback_paths` 里的路径）。

#### 反代 / 隧道场景

网关支持把面板与回调一起暴露到公网（nginx、frp、Cloudflare Tunnel 等）。此时：

- 面板「设置」里填 **外部访问地址**（如 `https://gw.example.com`）。填了它就以它为准；
- 未填时，网关会**按登录请求的转发头自动推导**（仅采信直连方为回环的 `X-Forwarded-*`），
  所以你即便不填，只要反代正确转发了 `X-Forwarded-Proto` / `X-Forwarded-Host` 也能工作；
- **反代必须把路径原样透传到网关根路径**（例如 nginx `proxy_pass http://127.0.0.1:8787/;`
  带结尾斜杠）。网关**不支持**挂在 `/gw/` 之类的路径前缀下——不要在外部地址里带路径。

### 6.8 面板行为速览

- 只有插件**运行中**时「控制台」按钮可用
- 打开后每 20 秒自动刷新账号列表；手动「刷新」可立即刷新
- `notice` 非空时在顶部显示常驻提示条
- 登录按钮由插件声明的 `login_methods` 决定，面板不写死任何登录方式
- 声明了 `fields` 的方法：点按钮先展开输入表单，提交后把值 POST 给插件；未声明的仍是「点一下即完成」
- `link` 类登录每 2 秒轮询，**无次数上限**，用户可点「取消」终止；同时只跟踪一个登录会话
- `link` 类登录等待期间，面板提供「粘贴回调链接」输入框：Docker 下回调页打不开时，把地址栏完整链接粘进来即可
- 账号列表的列与按钮由 `capabilities` 决定（`checkin` / `quota`）
- 所有操作走 toast 反馈，失败展示插件返回的 `error`

参考实现见 `examples/workbuddy/`：含完整的账号 / 签到 / 额度，以及三种登录方式（本机登录态导入 + 国内站/国际站 OAuth）。

## 7. 生命周期与状态

```
discovered ──▶ starting ──▶ running ──┬──▶ unhealthy ──▶ restarting ──▶ running
                                      └──▶ failed（连续失败超限，放弃自动重启）
running/任何状态 ──▶ stopped（宿主停止或用户停用）
```

| 行为 | 规则 |
|---|---|
| 探活 | 每 2 秒一次，单次超时 2 秒；连续 3 次失败判定 `unhealthy` |
| 重启 | 不健康或进程退出即重启，退避 1s/2s/4s/8s/16s |
| 放弃 | 连续失败 5 次后置 `failed` 并停止自动重启（面板会展示 `last_error`） |
| 启动超时 | 超过 `startup_timeout_ms` 仍未探活通过，判为启动失败 |
| 优雅停止 | 先发 Ctrl-Break（Windows）/ SIGTERM（类 Unix），等待 5 秒，再强杀 |
| 退出回收 | 插件进程及其子进程挂在 Windows 作业对象上，网关退出时整棵树一起回收 |

#### `/health` 只回答一个问题：插件进程自己还活着吗

- 口径：`GET /health` 返回状态码 **< 500** 即视为存活（`2xx` / `3xx` / `4xx` 都算活着；`5xx` 与连不上算失败）。
- **不要把上游健康、账号登录态、额度、模型可用性塞进 `/health`。** 上游抖动或某个账号过期是常态，
  一旦 `/health` 跟着返 `5xx`，网关会判定插件不健康 → 重启 → 连续 5 次后直接置 `failed` 并**停止自动重启**——
  一个上游问题被放大成插件永久不可用。
- 账号级别的状态请放进 `GET /console/accounts`（`enabled` / `last_error` / `expires_at`），那里才是它的家。

#### 启动期与运行期的判定不同

| 阶段 | 判定 |
|---|---|
| 启动（`starting`） | 每 300ms 探一次，直到 `startup_timeout_ms` 用尽；**一次成功即视为就绪**，不看"连续失败次数"；超时即启动失败并进入退避重启 |
| 运行（`running`） | 每 2 秒探一次，**连续 3 次**失败才算 `unhealthy` 并触发重启 |

失败计数在每次成功进入 `running` 时归零；**连续 5 次失败**（跨重启累计）后置 `failed`、停止自动重启，
需要用户手动点「启动」才恢复。端口被占用也算一次失败，`last_error` 会给出"换一个端口"的提示。

插件应处理停止信号并尽快退出：

```python
import signal

def stop(*_):
    server.shutdown()   # http.server：关闭监听并让 serve_forever 返回
    raise SystemExit(0)

for sig in (signal.SIGINT, signal.SIGTERM, getattr(signal, "SIGBREAK", signal.SIGTERM)):
    signal.signal(sig, stop)
```

## 8. 安全约束

- `entry` 不允许绝对路径，也不允许 `..` 逃逸出插件目录（校验失败插件不会启动）
- 插件凭据不进入网关数据库；日志与控制台接口中不出现明文凭据（含 `last_error`）
- 插件只应监听 `127.0.0.1` 的 `port` 一个端口，**不得监听任何额外端口**（登录回调由网关统一入口托管，见 §6.7）
- 统一回调入口 `/plugin-callback/*` **免鉴权**且可能暴露到公网，因此 `state` 校验是硬要求（见 §6.7）
- 请只使用你**本人账号的正当额度**；不要实现任何绕过上游额度或风控的功能

## 9. 调试与排错

排错入口：

- 插件列表 / 状态 / 端口：桌面窗口的「插件」区（点「重扫」重新读取插件目录）
- 运行日志（含插件 stdout/stderr 转发，每行以 `[plugin:<插件id>]` 为前缀，便于区分是哪个插件打出来的）：桌面窗口底部的日志区

常见问题：

| 现象 | 原因 / 处理 |
|---|---|
| 面板里看不到插件 | 目录名不合规（2–32 位、首字符须为字母/数字，其余为小写字母/数字/`-`/`_`）；或缺 `plugin.json`；或校验失败（看日志） |
| 状态一直 `starting` | 探活没过：没监听 `AI_GATEWAY_PLUGIN_PORT`、没实现 `GET /health`、启动太慢（调大 `startup_timeout_ms`） |
| 状态 `failed` 且 `last_error` 提示端口被占用 | `port` 与别的程序冲突，改 `plugin.json` 里的 `port` 后点「启动」 |
| 状态 `failed` | 连续 5 次失败已放弃；看面板 `last_error` 与日志，修好后点「启动」 |
| 渠道里没有模型 | 模型不自动填充。插件需实现 `GET /v1/models`（形状见 §2），再在「渠道管理」编辑该渠道、点「获取上游模型」后勾选 |
| 转发报 502 | 插件进程没起来，或没监听清单里写的 `port` |
| 一个坏模型把渠道里所有账号都试了一遍 | 你把该错误映射成了 `404` / `429` / `5xx` 之一。请求本身的问题请返回 `400`（见 §5.2） |
| 客户端看到的报错只有半句话 | OpenAI 入口只透传你响应体的**前 300 字节**，把错误文案压到 300 字节内（见 §5.3） |
| 插件反复重启，最终 `failed` | `/health` 跟着上游状态一起失败了（见 §7）。`/health` 只应反映插件进程自身，账号/上游状态放 `/console/accounts` |
| 控制台报 409 | 宿主判定"插件未就绪"：插件不存在 / 未声明 `console` / 未运行（插件自己的 4xx 会原样透传，见 §6.2） |
| 控制台请求 404 | 实际路由与约定接口不匹配（见 §6.3）；若来自插件本身，则是插件侧没实现该端点 |
| 面板没有「签到 / 额度」按钮 | 清单里 `capabilities` 没声明 `checkin` / `quota` |
| 控制台一直「正在等待授权…」 | 登录接口一直返回 `pending`。给 `state` 设过期时间、超时返回 `expired`（见 §6.6） |
| 反代 / 隧道下授权后回调一直不通 | 回调地址拼成了 `127.0.0.1`。请在面板「设置」填外部访问地址，或让反代转发 `X-Forwarded-Proto` / `X-Forwarded-Host`；反代还需把 `/plugin-callback/` 原样透传到网关根路径（见 §6.7） |
| 回调页报「插件当前不可用」 | 插件未运行 / 未声明 `console`，网关没有转发。回面板确认插件状态后重试 |
| 回调请求返回 405 | 上游重定向用了 POST 或其它方法。网关只放行 `GET`，请改用授权码模式的 `GET` 重定向 |
| 面板上加不了账号 | 插件只实现了 `POST /accounts`，但没返回 `login_methods`——面板没有表单入口（见 §6.3 / §6.6） |
| 插件报 `entry 必须是 .py 脚本` | 网关只支持 Python 插件，入口脚本必须以 `.py` 结尾（见 §2） |

## 10. 分发给其他用户

一个插件就是 `plugins/<id>/` 整个目录，打包成 zip 即可分发。注意：

1. 目录名就是插件 id（2–32 位，首字符为字母/数字，其余为小写字母/数字/`-`/`_`）
2. 入口文件与清单都在目录内，不要依赖目录外的路径
3. 依赖只用 Python 标准库，或写进 `requirements`（宿主会自动装进插件私有目录，见 §11.2）；
   不要要求用户手工 `pip install`
4. 凭据、缓存等可写内容一律放 `AI_GATEWAY_PLUGIN_DATA`，不要写进插件目录
   （插件目录可能被整体覆盖升级）
5. **数据目录的升级由你自己负责**：`AI_GATEWAY_PLUGIN_DATA` 不会被覆盖，
   建议在里面放一个 schema 版本标记（如 `state.json` 里的 `"schema": 3`），新版启动时先读它再决定是否迁移；
   `plugin.json` 的 `version` 只用于面板展示，网关不会据此做任何迁移

## 11. Python 运行时：一份源码跨平台

**网关只支持 Python 插件**（见 §2）：`entry` 必须是插件目录内的 `.py` 脚本，交给 Python 解释器执行。
同一份 `main.py` 原样复制到 Windows / macOS / Linux（含 Docker）都能运行，
不需要为每个平台准备不同的启动壳或编译产物。清单里**不需要**再声明运行时。

```json
{
  "name": "Hello Python",
  "entry": "main.py",
  "port": 20801,
  "requirements": ["httpx>=0.27"]
}
```

插件侧要做的与任何进程插件完全一样：监听 `AI_GATEWAY_PLUGIN_PORT`、实现 `GET /health` 与
`POST /v1/chat/completions`（见 §2）。区别只在于**是谁把进程拉起来**。

### 11.1 解释器从哪来

宿主按顺序解析，找到即用：

1. **系统 Python**：Windows 依次尝试 `py -3` → `python3` → `python`（会自动跳过应用商店的占位程序）；
   macOS / Linux 依次尝试 `python3` → `python`。只接受 Python 3。
2. **便携 Python**：`<数据目录>/runtime/python/<版本>/`（可在面板「设置 → 便携 Python 目录」改位置，
   或设置环境变量 `AIGW_PYTHON_RUNTIME_DIR`）。
3. 都没有 → 插件以 `failed` 停下，`last_error` 给出安装指引。**宿主不会在启动流程里自动下载**。

便携 Python 由用户在面板「设置 → Python 插件运行时」点「下载便携 Python」显式获取：
默认从 python-build-standalone 官方发布地址下载，下载完成后校验、解压到便携目录（临时目录 + 原子改名）。
国内或内网可自行转存一份，并把「便携 Python 下载地址」填成镜像前缀（**文件名与官方保持一致**）。
也可以手工解压后放进便携目录，宿主会直接识别。

> 便携 Python 不随网关安装包分发，安装包体积不变；只有真正用 Python 插件的机器才需要这一份运行时。

### 11.2 依赖安装

声明 `requirements` 时，宿主用 pip 把包装进**插件私有目录** `<AI_GATEWAY_PLUGIN_DATA>/deps`，
启动时通过 `PYTHONPATH` 注入，不会污染系统 Python，也不会装到插件目录里。

- **源顺序**：官方源 `https://pypi.org/simple` 优先，失败后依次退避到清华、阿里云、腾讯云、中科大镜像；
  每次只向 pip 传一个 `--index-url`（不使用多源合并，避免同名包来源不确定）。
- **缓存**：成功的源与 `requirements` 指纹一起写入 `deps/.pip.lock`，24 小时内同指纹同解释器版本直接复用。
- **自定义**：面板「设置 → pip 源」可填写自己的源列表（逗号分隔），填了就不再使用内置列表；
  也可用环境变量 `AIGW_PIP_INDEX_URLS`。内网环境建议全部指向内网源。
- **失败提示**：所有源都失败时，`last_error` 会列出每个源的具体原因，便于判断是网络、证书还是包不存在。
- 只使用标准库的插件**完全不会触发 pip**。

### 11.3 运行时注入的环境变量

除 §4 的公用变量外，宿主额外设置：

| 变量 | 作用 |
|---|---|
| `PYTHONUNBUFFERED=1` | 关闭输出缓冲，日志实时进入网关 |
| `PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8` | 强制 UTF-8，避免 Windows 默认 GBK 导致中文乱码 |
| `PYTHONPATH=<deps>` | 让已安装的依赖可被 `import`（仅声明了 `requirements` 时） |

### 11.4 示例

`examples/hello-py/` 是一个只用标准库的最小实现（`http.server` + `json`），
复制到 `plugins/hello-py/` 后点面板「重新扫描」即可拉起。它同时演示了
`/health`、`/v1/models`、`/v1/chat/completions` 三个端点以及按 `X-Plugin-Account` 取账号。

### 11.5 注意事项

- **停止信号**：Unix 收 `SIGTERM`，Windows 收 `Ctrl-Break`（Python 里的 `signal.SIGBREAK`）。
  桌面 GUI 无控制台时会退化为强杀，所以账号与状态**必须原子落盘**（写临时文件再 rename）。
- **只监听一个端口**：与其它插件一致，登录回调走网关的 `/plugin-callback/<id>/...`。
- **macOS Gatekeeper**：宿主会自动清理便携 Python 的 quarantine 属性；手工放入的可执行文件如被拦截，
  执行 `xattr -dr com.apple.quarantine <目录>`。
- **Alpine / musl**：便携 Python 默认取 glibc 版本；Alpine 基础镜像本身通常已带 `python3`，
  会走系统 Python，无需下载。
