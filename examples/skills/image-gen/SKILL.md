# 生图提示词经验

本文件不重复工具用法：`initialize` 的 `instructions` 与每个工具的 `description` 已经说明了
调用流程、参数、上限、错误结构和返回链接的有效期，直接以那里为准。这里只保留写提示词、
安排参考图、挑选模型这类无法写进 schema 的经验。

## 写提示词

- 描述**最终画面**，不要描述过程：主体、动作、环境、光线、镜头、材质、风格各说清一句。
- 具体优于抽象：「磨砂玻璃质感的桌面」比「高级感」有效。
- 一次只改一个变量做对比；同时改风格、构图、光线，很难判断是哪项起作用。
- 需要图中文字时，把文字用引号原样写出，并说明位置；文字较多的海报类任务，先做小尺寸试稿。
- 负向需求（不要什么）放 `negative_prompt`，不要在正向提示词里写「不要……」。
- 需要稳定复现时固定 `seed`，其余参数保持不变。

## 参考图

- **顺序即编号**：`image_url` / `image_path` 的第 1 张就是提示词里的 Picture 1。
- 在提示词里写清每张图的职责，例如「Picture 1 只提供背景，Picture 2 只提供人物姿态」，
  不要假设模型会自动分清主次。
- 图生图改细节时，提示词要同时描述「保留什么」和「改变什么」，否则容易整体重绘。
- 参考图只作风格参考时，明确写「只参考色调与光线，不参考内容」。
- 参考图本身越干净越好：带水印、拼贴、多主体的图会把干扰带进结果。
- 需要多视角、多版本时，逐张单独生成，比一次塞多张参考图更可控。

## 选模型

- 带参考图的任务优先选明确支持图生图 / 编辑的模型；纯文生图模型会忽略或弱化参考图。
- 同一提示词在不同模型上的风格差异明显，横评时保持尺寸、张数、种子一致。
- 出图模糊、文字糊、尺寸不支持，多半是模型能力边界，不属于网关问题；换模型比调参数有效。
- 具体模型清单与默认模型，以 MCP 的 `list_image_models` 返回为准。
